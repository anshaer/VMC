# 多平板分區控制 v1.2

## 最基本：一台面部，一台肢體

1. 電腦開本版 receiver.html；Warudo 接收頁連好插件 v0.2。
2. 平板 A 選「面部＋頭部」，輸入接收頁的碼並連線。
3. 平板 B 選「身體＋肢體」，輸入同一碼並連線。
4. 接收頁列出來源與控制區域，合併成一份 OSC/VMC。
5. 每台可隨時改「控制區域」，下一個影格套用新分區。

Warudo 平板可選全部、面部＋頭部、身體＋肢體、軀幹、左右手臂、雙手掌／手指、左右手掌／手指、雙腿／腳與根位置。
2D 平板保持面部用途；2D 接收診斷頁也使用多來源核心，收到身體資料時仍只是診斷，不會增加正式角色的肢體渲染功能。

## 規則

- 最多 8 個同時來源；不是傳輸影格計數。第 9 台會被拒絕，需等有位置後重新連線。
- 同區重疊時，按接收端目前的連線順序，第一個仍有新資料的來源優先，不按封包抵達先後來回切。
- 區域中實際沒收到對應資料，不會占用該區。
- 一台「全部」可能占用所有區；分工時務必改成指定區域。
- 每來源只留一份當前資料，3 秒未更新即釋放；其他新鮮來源可作備援。
- 有來源繼續更新時，沒有備援的缺失骨骼區域使用中性參考姿勢。這不是個人模型的自動校正。
- 所有來源都失效時，不持續產生新動作；Warudo 可能保持最後姿勢。
- 方向事件來自任意已配對來源，使用獨立事件編號轉送並回覆原發送台，避免兩台本機 seq 相同造成誤判。
- 手機沿用既有協定：面部模式自動視作面部來源；身體模式按實際有資料的區域參與。手機頁尚無細分區域選單。
- 配對碼持有人可接入控制，請只分享給要操作的人。

## 骨骼依存關係

這是控制分工，不是多鏡頭三維融合。合併局部骨骼旋轉後仍遵循父子關係。
例如面部來源控制 Head、肢體來源控制 Neck／Chest；肢體轉動會改變頭在世界中的方向。
不同相機的骨架座標不能直接套用這種分區方式當作多視角融合。

## 平板介面

- 預覽預設收合，展開為小畫面；收合時不繪製預覽，操作區為主。
- 面部放開歸零：面部、轉頭、視線與2D深度。
- 身體放開歸零：骨骼角度、十指握拳快捷、Root位移。
- 兩個開關彼此獨立；表情／姿勢按鈕仍使用自己的按住生效開關。
- 請先選區域，再連線；其他區域的滑桿值可能仍合成於原封包，但接收端不採用。

## 測試

兩個實際接收 HTML 與三個平板控制程式的 DOM 測試通過：面部／身體分工、重疊區優先、3秒備援切換、在線改區、獨立歸零、預覽收合、同 seq 回覆、8 台限制、關頁計時器清理。
兩台平板 → Warudo接收頁合併 → 實際本機 WebSocket → C# 插件 → UDP 測試通過，面部／手肘值與兩台方向回覆正確。
WebRTC 配對使用測試 Peer 物件；C# Warudo API 使用測試替身。實體平板、跨網路、多設備效能與真實 Warudo 模型仍需測試。
